## Naming Conventions

### Files
- Components: `kebab-case.tsx` (e.g., `diet-list-screen.tsx`, `badge.tsx`)
- Style hooks: `kebab-case.styles.ts` (e.g., `badge.styles.ts`)
- Service functions: `kebab-case.service.ts` (e.g., `generate-diet.service.ts`)
- React Query hooks: `use[PascalCase].ts` (e.g., `useGetDietPlanList.ts`)
- Barrel exports: `index.ts`
- Type files: `types.ts` or `[name].model.ts`

### Components / Exports
- Component functions: PascalCase (e.g., `Badge`, `DietListScreen`)
- Style hook functions: `use[ComponentName]Styles` (e.g., `useBadgeStyles`)
- React Query hooks: `use[Action][Resource]` (e.g., `useGetDietPlanList`)
- Service functions: `[action][Resource]Service` (e.g., `generateDietService`)
- Constants: SCREAMING_SNAKE_CASE (e.g., `WEEKS`, `ITEM_WIDTH`)
- Enums: PascalCase variants (e.g., `ActivityLevel.Sedentary`)

### Directories
- Shared UI: PascalCase (e.g., `src/shared/ui/Badge/`)
- Module components and screens: kebab-case (e.g., `diet-list-screen/`, `meal-card/`)

## Code Style

### Imports
- Path alias `@/` resolves to `src/` — used for all non-relative imports
- External/third-party imports first, then `@/` alias imports, then relative imports
- Named exports only — no default exports

### Exports
- Named exports everywhere (no `export default`)
- Barrel `index.ts` in every component/use-case directory
- Types exported alongside implementation (co-located)

### Types / Interfaces
- `interface` for object shapes and props (e.g., `interface BadgeProps`, `interface Profile`)
- `enum` for fixed value sets (e.g., `ActivityLevel`, `SubscriptionTier`)
- `const enum` for inlined enums (e.g., `SubscriptionTier`)
- `type` for unions and aliases
- DTO types suffixed with `DTO` (e.g., `ProfileDTO`, `DietPlanDTO`)
- Prop interfaces suffixed with `Props` (e.g., `BadgeProps`)

## Component Architecture

Each UI component follows a 3-file structure:
```
ComponentName/
├── component-name.tsx        ← Component function (PascalCase export)
├── component-name.styles.ts  ← Style hook (useComponentNameStyles)
└── index.ts                  ← Barrel: export * from './component-name'
```

Complex components may add:
- `component-name.animated.ts` — Reanimated values/shared values
- `component-name.viewmodel.ts` — Local state / business logic hook
- `component-name.service.ts` — Component-scoped service
- `library/` — Internal sub-components

## Use Case Architecture

Each use case follows a 3-file structure:
```
use-case-name/
├── use-case-name.service.ts  ← Pure async function (no React)
├── useUseCaseName.ts         ← React Query hook (useQuery/useMutation)
└── index.ts                  ← Barrel export
```

## State Management

- **Server state**: TanStack Query v5 (`@tanstack/react-query`) — all API calls
- **DI container**: Custom `DIContext` + `useDIContainer` hook for service injection
- **Local state**: `useState` / `useReducer` for component-scoped state
- **Persistent state**: `react-native-mmkv` for local key-value storage
- No Redux, Zustand, MobX, or other global client state library

## API Layer

- **REST API**: Axios client in `src/infra/api/` (`baseURL: http://localhost:8000`)
- **Database / Auth**: Supabase JS SDK (`src/infra/config/supabase/`)
- **AI services**: Custom adapter in `src/infra/adapters/ai/`
- Repository pattern: `IBaseRepositoryBuilder` abstracted behind DI container

## Testing

No unit or integration test suite. Project is intentionally untested at the unit level.
